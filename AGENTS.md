# Repository Guidelines

## Project Overview
`oomph`: minimal self-hosted web UI for the `omp` coding agent (`/usr/bin/omp`, package `@oh-my-pi/pi-coding-agent`), packaged as an **omp plugin** published to npm as `@dzhi/oomph` (npm user `dzhi`). Single-user, password-protected, plain HTTP; binds `127.0.0.1` (default) or `0.0.0.0`. How it's exposed (reverse proxy, tunnel, Tailscale/WireGuard/ZeroTier, LAN) is the user's choice; nothing is Tailscale-specific. Git repo (origin `git@github.com:pentago/oomph.git`). The client UI was originally ported from OMPiUI (GPL-3.0); the user had all attribution comments removed (2026-09-30 decision) — do not re-add them. `dist/` is gitignored and only shipped in the npm package; `README.md` is user-facing, in plain non-technical English (keep it that way and in sync with `/oomph` commands/settings). CI: `.github/workflows/ci.yml` (PRs to `main`: `bun run check`) and `publish.yml` (`v*` tag → `npm publish` via npm trusted publishing/OIDC, no token; tag must equal `v` + package.json version).

## Architecture & Data Flow
```
Browser (Preact SPA) <--WebSocket /ws (JSON)--> server.ts (Bun.serve) --+--stdin/stdout NDJSON--> `omp --mode rpc` child (chats no terminal has open)
                                                      |                  +--lifeline unix socket--> terminal omp's plugin (the chat that omp has open)
                                                      +--reads <OMP_AGENT_DIR>/sessions/<dir>/*.jsonl directly for history + session list
```
- **Plugin** (`extension.ts`, manifest `omp` in `package.json`): omp loads the extension into *every* omp process (incl. the RPC children oomph spawns), so everything is gated on `main(ctx)` = `ctx.hasUI && ctx.agent.kind === "main"`. It registers `/oomph [status|start|stop|restart|passwd|autostart [on|off]]`, autostarts on `session_start` (setting `autostart`, default **on**; off still joins a running server), and `/oomph autostart on|off` writes the setting via `new PluginManager(cwd).setPluginSetting`. `start` spawns `server.ts` in its own process group via `process.execPath` + `BUN_BE_BUN=1` (omp is a compiled Bun binary; no system bun needed) with `OOMPH_LIFELINE=$OOMPH_CONFIG/lifeline.sock`, logs to `$OOMPH_CONFIG/server.log`, polls `http://127.0.0.1:<port>/login`, then `hold()`s the lifeline connection for the life of that omp. If the port answers but `hold()` fails: pid file present = server started outside omp (leave it); absent = our server shutting down (wait, then start fresh). **Lifetime = lifeline**: the server counts connected holders and shuts down at 0 (the OS closes the socket on any omp exit, crash included), or after 30 s if nobody ever connects. `server.ts` without `OOMPH_LIFELINE` (dev.sh, manual runs; the lifeline/bridge tests set it for their own second server) has no lifeline and no terminal bridge. **No systemd, by user decision.** First start generates a random password and shows it once via `ctx.ui.notify` (UI only, not persisted to the session JSONL); `/oomph passwd` regenerates. Settings come from `getPluginSettings` (`@oh-my-pi/pi-coding-agent/extensibility/plugins`, resolved by omp at load time) with defaults from the manifest. `omp.d.ts` declares just the API slice used; the real package is too heavy to install for types.
- **Terminal bridge** (why: omp has no cross-process session lock, so a second omp on a chat open in a terminal forks it). The lifeline connection carries NDJSON: plugin → server `{t:"claim", file}` (sent on connect and whenever the open chat changes) and `{t:"frame", frame}`; server → plugin `omp --mode rpc` commands. The plugin emulates rpc: it relays agent/message/tool extension events as rpc-shaped frames (message id = `t<message.timestamp>`, stable across start/update/end; late `message_update` after `message_end` is dropped, omp can deliver it after the end) and answers `prompt` (`sendUserMessage`, `followUp` while busy), `abort`, `get_state`, `get_available_thinking_levels` (`off` + `model.thinking.efforts` if `reasoning`), `get_available_models`, `set_model`, `set_thinking_level`. Server: `Sess` has either `owner` (holder socket) or `proc` (our child), never both; `claims` maps file → holder. `claim()` kills our child for that chat and rebinds the session (same key) to the terminal; `release()` (terminal switched chat or exited) respawns a child if browsers are still watching. `listSessions` marks claimed files as running. Known gaps: a turn our child is mid-way through when a terminal claims the chat is cut off; frames are relayed even when no browser watches; model changes made in the terminal reach the browser on the next `turn_end` state refresh.
- **Bridge hardening** (the lifeline socket carries prompts and lets a peer drive chats): socket `chmod 0600`, `$OOMPH_CONFIG` `chmod 0700`; `claim` and `delete` paths must pass `isSessionFile` (inside `SESSIONS_DIR`, `.jsonl`, and `resolve(file) === file` so a `..` path is rejected); per-connection line buffer capped at 64 MB; both sides queue partial socket writes and finish them on `drain` (`sendTo`/`flushTo` in server, `send`/`flush` in plugin), so big frames never arrive cut off; every plugin `pi.on` handler is wrapped so an oomph error never reaches omp's TUI; `runChild` returns false if `omp` can't be spawned (open → error, release → `exited`). The server also drops a `message_update` for a message that already got its `message_end` (`Sess.ended`), for both terminal and child-owned chats.
- **No SDK, no framework.** Server = one file (`server.ts`) using only Bun/node builtins. A chat no terminal has open gets `runChild()`: `omp --mode rpc --no-ui --allow-home [--resume <file>]` in the session `cwd`. `--allow-home` is required or omp relocates `~` sessions to a temp dir.
- **RPC layer** (`server.ts`): `write()` sends `{id:"r<seq>",...cmd}`; `rpc()` correlates `type:"response"` frames via `Sess.pending`; slash commands typed in the browser run in the session's omp (omp parses `/cmd` prompts) and their `command_output` frames are emitted as `note` messages; `pump()` reads stdout lines; `onFrame()` maps omp frames → `UiEvent`. stderr is discarded.
- **State is in-memory, module-level**: `sessions: Map<uuid, Sess>` (with `subs: Set<ws>`), `modelCache` (5 min), `metaCache` (per file, by mtime), `gzCache`, login `failures/lockedUntil`. Closing a WS only unsubscribes; the omp process keeps running. Multiple browsers can watch one session. Idle reaper (60 s tick) kills procs with no subscribers, not streaming, idle > 30 min. `shutdown()` (SIGTERM/SIGINT/last lifeline holder gone) kills all children and removes `$OOMPH_CONFIG/pid` (written once listening; `/oomph stop` reads it) and the lifeline socket.
- `server.ts` deletes `BUN_BE_BUN` and spawns children with `env: process.env` explicitly: Bun.spawn's default env is a startup snapshot, so without it the `omp` children would run as bun.
- **Browser terminal** (`server.ts` "browser terminal" section, `client/components/TerminalPanel.tsx`): the `>_` button in the composer toggles a full-width docked panel below it. Several shells per WebSocket (max 16, named by a client-chosen `id`) in `terms` (a map of maps; `Bun.spawn(..., { terminal })` = a real PTY; `$SHELL` or `/bin/sh`, cwd = the active chat's cwd, `OOMPH_LIFELINE` stripped from its env); output streams as `term` JSON through a streaming `TextDecoder`, input is `termIn`, size is `termResize`, every message carries the `id`. `termOpen` must stay synchronous (messages are handled concurrently, an `await` would drop the first keystrokes). A shell is killed with `terminal.close()` + SIGHUP (interactive shells ignore SIGTERM) on `termClose{id}`, socket close or shutdown; `exit` sends `termExit{id}`. The panel (`TerminalPanel`) has IDE-style tabs (x closes, + adds), and a split button that adds a side-by-side pane (max 4) to the active tab; the top edge has a drag grip (three dots, `cursor: row-resize`) that resizes the panel, min 120 px and CSS-capped at `100dvh - 10rem`, height saved in localStorage `oomph-term-height`; each pane is a `TermPane` = one xterm + one shell. A pane or tab disappears when its shell exits; when the last one goes the panel closes. It stays mounted while hidden (scrollback survives toggling) and remounts, i.e. starts new shells, on every WS reconnect (`conn` key in `App.tsx`). Frontend is xterm.js (`@xterm/xterm` + `addon-fit`, css imported in `client/index.css`, not from TS: a CSS import in `bun build` would emit `dist/app.css` and clobber the Tailwind output); colors come from the theme tokens and refresh on theme changes; the font is the generic `monospace` on purpose (a browser can't use the user's terminal font, and the oomph mono font would just be a second look). Tabs are square, Zed-style: a `bg-bg-100` bar, `>_` icon + label + always-visible x, dividers between tabs, the active tab on `bg-bg-000` (the terminal body's color, so it reads as brighter in light and dark). The env is inherited untouched (tmux/starship vars from the terminal that launched omp included, deliberately: most users run omp in a multiplexer); only `OOMPH_LIFELINE` is dropped. `TerminalPanel` = tab bar + resize grip, `TermPane` = one xterm + one shell. It is a shell as the oomph user behind the same login as the agent. A plugin-started server keeps its old code until `/oomph restart` while the page is served fresh from `dist/`, so after changing the terminal protocol restart it or the new page will talk to an old server.
- **History** is read from the session JSONL (not RPC): walk the `parentId` chain from the last entry (active branch) and convert with `toUi`.
- **Contract**: `shared.ts` (types only; imported with `import type` by both sides). `ClientMsg`: `list | open{cwd?,file?,key?} | delete{file} | prompt | abort | models | setModel | setThinking | termOpen{id,cwd?,cols,rows} | termIn{id,data} | termResize{id,cols,rows} | termClose{id}` (`delete` stops our child for that chat, removes the `.jsonl` plus omp's sibling artifacts dir, and replies with a fresh `sessions` list; refused for chats a terminal omp has open; the sidebar trash button shows on hover/focus; the first click arms it (red "Delete?", auto-disarms on blur, mouseleave or after 3 s) and the second deletes; deleting the open chat starts a fresh one). `sessions` also carries `defaultModel?` (one-time omp probe per server start, so the composer shows a model before any chat). `ServerMsg`: `sessions | opened | ev{key,ev:UiEvent} | models | term{id,data} | termExit{id} | error`. `UiEvent`: `agent_start/agent_end/start/delta/msg/tool_start/tool_end/state/commands/result/exited` (`commands` + the `opened` reply carry the session's slash-command list, from the child's `available_commands_update`; the composer shows a `/` menu from it — child-owned chats only, terminal bridge has no command API). A `msg` event replaces the streamed message with the same `id`. Change protocol in `shared.ts` first, then server, then `client/App.tsx`. Invalid JSON / unknown keys from the client are silently ignored.
- **Truncation limits** live in server (text 50k; user/tool/thinking 20k; tool args 4k; details 20k; oversize → `{_truncated}` via `limitJson`).
- **Auth**: argon2id hash (`Bun.password`) in `$OOMPH_CONFIG/password` (plugin: random 24 chars; `bun server.ts passwd`: min 12 chars); cookie `oomph_session` = `<expiry>.<HMAC>` (HttpOnly, SameSite=Strict, 30 d, `Secure` only when the request Origin is `https:` so plain-HTTP LAN/VPN access works), keyed by `secret` file + password hash (changing password invalidates cookies). One *global* exponential login backoff (deliberate: proxies hide client IPs). No Host allowlist; POST and `/ws` require an `Origin` whose host equals `X-Forwarded-Host ?? Host`. CSP forbids inline scripts (hence `client/assets/theme-init.js`).
- **Client state**: no store/router/context. `client/App.tsx` owns everything via `useState`; props down, callbacks up; prop contracts in `client/components/props.ts`. `activeRef` mirrors `active` for WS closures. `applyEvent()` is the pure reducer folding `UiEvent` into messages. WS auto-reconnects (2 s), re-sends `open` for the active session; session list polled every 15 s and refreshed on `visibilitychange`. `send()` queues into `outbox` while the WS is down (only the newest queued `open` survives). `opened` replies carry `state` (model + thinking levels), which the client applies; the model/thinking pickers need a live omp, so the new-chat view auto-opens a chat once online and `cwds` are known (`openNew()`, guarded by `activeRef`/`starting`; effect deps are `[online, cwds.length]`, so a failed open is not retried until reconnect). `welcome = !active || msgs.length === 0` shows the centered composer; header title is `"oomph"` until the chat has messages. `open()` confirms before opening a non-running session touched <2 min ago (another omp may own it).
- **Markdown pipeline** (`client/components/messages/Markdown.tsx`): `marked` → `splitBlocks()` (stable per-block keys so memo skips finished blocks while streaming) → html blocks sanitized by DOMPurify then applied via `morphdom` into a div Preact never diffs; tables are Preact components; code → `CodeBlock` → `highlight.ts` (shiki/core, JS regex engine, 16 langs, `LANGUAGE_FALLBACKS` for ts/js/jsx→tsx, cpp→c; 100k-char cap).

## Key Directories
- `/` — `server.ts` (all backend), `extension.ts` (omp plugin entry), `omp.d.ts` (omp API types), `shared.ts` (wire types), `package.json` (also the plugin manifest), `tsconfig.json`, `server.test.ts` (integration suite).
- `client/` — SPA: `main.tsx`, `App.tsx`, `theme.ts` (+ `themes.ts` palettes, `fonts.ts` Google Fonts list), `index.html`, `index.css` (Tailwind entry, imports `styles/theme.css` + `composer.css` + the xterm css). Look = Claude-style: sans UI / serif replies. Fonts: curated Google Fonts lists in `fonts.ts` (~20 each: sans / serif / mono), defaults Inter (interface) / Source Serif 4 (replies) / JetBrains Mono (code). No fonts are bundled in the package; the browser loads picks on demand. Font vars: `--font-ui-sans`, `--font-sidebar`, `--font-chat`, `--font-mono`.
- `client/components/` — `Sidebar`, `Header`, `Composer`, `ModelSelector`, `SettingsDialog`, `Logo` (5 fading triangles: app mark, and the busy spinner when given `animate-spin`), `TerminalPanel` (xterm tabs/splits, see Browser terminal), `props.ts`; context usage lives in `sidebar/SidebarFooter`; `sidebar/` (SessionRow, SidebarFooter, useIsMobile); `messages/` (MessageList, MessageRows, tools/toolOutput/toolSummary, Markdown, CodeBlock, highlight, Reasoning, Collapse, disclosure, ansi, …).
- `client/assets/` — static files served at `/assets/*` (`theme-init.js`: pre-paint dark-mode; keep in sync with `theme.ts`; plus the PWA set: `icon.svg`/`icon-192.png`/`icon-512.png` served as `/assets/icon*`, and `manifest.webmanifest`/`sw.js` (a no-op service worker, registered in `main.tsx`, purely so the app is installable) served at the root paths `/manifest.webmanifest` and `/sw.js` — the worker must live at the root so its scope covers the app). All PWA files are served **without auth** (`PWA_FILES` in `server.ts`, deliberately: the browser fetches them without the cookie); every other path requires login.
- `dist/` — generated `app.js` / `app.css`, gitignored. Built by `prepack` on publish and shipped only in the npm package (`files` in `package.json`). Never edit by hand.
- `scripts/dev.sh` — throwaway dev instance: rebuilds, wipes/recreates its config dir if `password` is missing, and `unset`s `OOMPH_LIFELINE` so it never touches the real plugin's socket (matters when launched from inside omp).
- `static/` — repo-only images for the README (`oomph-web-ui-screenshot.png`); not in `package.json` `files`, so npmjs renders it from the GitHub repo.
- `.github/workflows/` — `ci.yml` (PRs to `main`: `bun run check`) and `publish.yml` (`v*` tag).

## Development Commands
```bash
bun install
bun run build            # tailwind CLI -> dist/app.css; bun build client/main.tsx -> dist/app.js (+BUILD_STAMP)
bun run start            # bun server.ts (default port 8788)
bun server.ts passwd     # set login password (server refuses to start without one)
scripts/dev.sh <name> <port>   # isolated instance: config /tmp/oomph-cfg-<name>, password dev-password-123, builds then serves
bun run check           # everything CI runs: biome ci --error-on-warnings (format+lint) → tsc → build → bun test
bun run format          # biome: apply formatting, import sorting, safe lint fixes
omp plugin link .        # install this checkout as a plugin (symlink); `omp plugin uninstall @dzhi/oomph` undoes it
omp plugin config set @dzhi/oomph host 0.0.0.0   # or port; then `/oomph restart` in omp (autostart: `/oomph autostart on|off`)
bun pm pack             # preview the npm package (runs prepack → build)
git tag v<version> && git push origin v<version>   # release: bump package.json version first; CI publishes
bun publish             # only for the very first release (npm needs the package before a Trusted Publisher can be linked: owner pentago, repo oomph, workflow publish.yml)
```
Server reads `client/index.html` and `dist/*` from disk per request → after client changes just rebuild + reload the browser; no server restart. Server changes need a restart.

Env vars: `OOMPH_CONFIG` (default `~/.config/oomph`; holds `password`, `secret`, `pid`, `lifeline.sock`, `server.log`), `OOMPH_HOST` (`127.0.0.1`), `OOMPH_PORT` (8788), `OOMPH_LIFELINE` (set by the plugin; `dev.sh` unsets it; the lifeline/bridge tests set it for their own second server), `OMP_AGENT_DIR` (`~/.omp/agent`). The plugin sets `OOMPH_HOST`/`OOMPH_PORT` from its settings (manifest defaults: `host` 127.0.0.1|0.0.0.0, `port` 8788, `autostart` true; README's settings table must match). `package.json` `files` ships only `server.ts`, `extension.ts`, `client/index.html`, `client/assets`, `dist` (`shared.ts`/`omp.d.ts` are type-only). Release: `publish.yml` on a `v*` tag checks the tag equals `v` + version, runs `bun run check`, then `npm publish`. There is no changelog.

Users install with `omp plugin install @dzhi/oomph` (npm). The plugin name (settings key, uninstall) is the package name `@dzhi/oomph`; the slash command stays `/oomph`. Why npm and not git: omp installs plugins with `bun install`, which installs `dependencies` but blocks install scripts (`prepare`/`postinstall`) of untrusted packages, so a git install can't build `dist/`. Running `bun server.ts` directly still works for dev or custom setups.

## Code Conventions & Common Patterns
- TypeScript strict, ESM. Biome (`biome.json`) formats and lints TS/TSX/CSS/JSON: 2-space indent, double quotes, semicolons, 120 cols, `x => y` arrows; `noImportantStyles` is off (reduced-motion/scrollbar overrides need `!important`). Fix lint properly; `biome-ignore` only with a stated reason. Terse comments explaining *why*.
- **Keep it minimal.** Single-file server, no framework. Deliberate shortcuts are marked `// ponytail: <ceiling / upgrade path>` — grep `ponytail:` for the full list (e.g. global login backoff, O(n) re-lex per delta, main-thread highlighting, dropped grammars, fixed font list). Use the same marker for new ones.
- Preact via `preact/hooks` and `preact/compat` (`memo`, `useSyncExternalStore`); JSX uses `class=` (not `className`) in own code. `tsconfig` `paths` alias `react`/`react-dom` → `preact/compat` solely so `lucide-react` resolves to Preact when bundled.
- Styling: Tailwind v4 utilities (CSS-first config in `client/index.css`, no tailwind.config); theme tokens as HSL CSS vars in `styles/theme.css` (`data-mode=light|dark`; `.glass` is just a solid-colour class); custom classes prefixed `oomph-`. Put only what utilities can't express in the CSS files. Appearance is client-only (localStorage): mode `oomph-theme`, theme/fonts/size `oomph-look`, cached inline css `oomph-paint` (restored pre-paint by `theme-init.js`), terminal panel height `oomph-term-height`. `themes.ts` holds the theme palettes (7 anchors + bg ramp each, sourced from the official upstream repos — see per-theme comments); `fonts.ts` holds the curated Google Fonts list (loaded by `<link>` from fonts.googleapis.com, allowed in the CSP). Base size = `<html>` font-size; all `--fs-*` are rem. Settings dialog: `components/SettingsDialog.tsx`, opened from the sidebar footer menu. Composer look (Claude-desktop style): rounded-[1.25rem] thin-border box, borderless text-style pills (+, model, thinking) left, send/stop `ml-auto` right; textarea rules in `styles/composer.css`.
- Message row components are `memo`'d: `buildItems()` in `MessageList.tsx` must keep props referentially stable. Expand/collapse state persists across remounts via `messages/disclosure.ts` (`useDisclosure(key, fallback)`).
- `send()` in `App.tsx` is an untyped `(o: object)` wrapper; keep payloads consistent with `ClientMsg`.
- Server errors: thrown in handlers → `{t:"error", error}` message shown as a note in the chat; process death → pending RPCs rejected with "omp exited", `{type:"exited"}` event emitted.
- All deps are devDependencies so a plugin install pulls in nothing. Client deps: preact, lucide-react, marked, dompurify, morphdom, shiki (16 langs), @xterm/xterm + addon-fit. No katex/clsx (removed).

## Important Files
- `server.ts` — routes (`/`, `/login`, `POST /logout`, `/ws`, `/app.js`, `/app.css`, `/assets/*`, `POST /upload`, plus the pre-auth PWA routes `/manifest.webmanifest`, `/sw.js`, `/assets/icon*`), auth, omp RPC, session listing (`listSessions`, 60 newest), `openSession`, `history`, security headers. `/app.js`/`/app.css` are gzip-compressed once per build (`gzCache`) and served with a content-hash ETag + `no-cache` revalidation — not mtime+size, deliberately: a rebuild mid-flight must never serve an old body under a new validator. `/upload` (auth + Origin guarded, 64 MB max) stores composer file attachments in `~/.local/share/oomph/uploads/<8hex>-<name>` (0700/0600) and returns `{path}`; the prompt then carries `Attached file: <path>` lines. Images ride in the prompt as real image content (max 8, each ≤8 MB base64, mime-checked); the composer downscales photos >300 KB to ~1568 px JPEG and falls back to `/upload` for formats the browser can't decode.
- `shared.ts` — wire protocol.
- `client/App.tsx` — WS client, reducer, top-level state.
- `client/components/messages/Markdown.tsx`, `highlight.ts` — largest client logic; bundle-size sensitive (`dist/app.js` ≈ 1.6 MB, shiki- and xterm-heavy).
- `client/index.css` (`@theme` token wiring, fs scale in rem, markdown-html rules) + `client/styles/theme.css` (GENERATED from `THEMES[0]` (Claude); the body regenerates byte-identically with `bun -e 'const { paletteVars, THEMES } = await import("./client/themes.ts"); for (const m of ["light", "dark"]) console.log((m === "light" ? ":root:root" : `:root:root[data-mode="dark"]`) + " {\n" + Object.entries(paletteVars(THEMES[0][m])).map(([k, v]) => `  ${k}: ${v};`).join("\n") + "\n}")'`, preceded by the file's 2-line `/* Generated from THEMES[0] … */` header comment, which the command does not emit).

## Runtime/Tooling Preferences
- **Bun** required (runtime, bundler, package manager, `bun.lock`). Do not use npm/yarn/node. Exception: `publish.yml` runs `npm publish`, because npm trusted publishing (OIDC) needs the npm CLI. Build script uses POSIX shell (`date`) quoting.
- Server must stay dependency-free (Bun/node builtins only); all npm deps are client-side and bundled.
- `0.0.0.0` exposes the login over plain HTTP on every interface; fine on a VPN, otherwise put TLS in front.
- `scripts/dev.sh` isolates only auth config (`OOMPH_CONFIG=/tmp/oomph-cfg-<name>`); it does NOT set `OMP_AGENT_DIR`, so it still reads/writes the real `~/.omp/agent` sessions. Set `OMP_AGENT_DIR` yourself for an isolated run.

## Testing & QA
- `bun run check` must pass (CI runs it on every PR to `main`). `server.test.ts` boots the real server on a random port with a temp `OOMPH_CONFIG`/`OMP_AGENT_DIR` and checks origin guard, auth gate, login cookie (no `Secure` on http), app files, install files load without a login (the pre-auth PWA routes), WS `list`, login lockout, the lifeline (stays up while any holder is connected, exits and cleans up when the last one closes), the terminal bridge with a fake terminal holder (browser state/prompts/deltas route through it — also the 0600 socket, a >1 MB frame arriving whole via the drain queue then truncated for the browser, and a late `message_update` dropped; CI has no omp, so spawning a child would fail the test), and the browser terminal (three shells with ids in one socket: independent input and pids, `exit` ends one, `termClose` kills one, closing the socket kills the rest; the main test server boots with `SHELL=/bin/sh` so it never depends on a user's shell rc, and death is polled with `Bun.sleep` because the shells are the server's children and there is no event to await). It needs `dist/` (built first by `check`). Real omp RPC and the plugin itself are only covered by manual runs.
- Beyond that, verification is manual: `scripts/dev.sh test 8799` and exercise the UI in a browser (open session, send prompt, streaming, tool cards, model switch).
- For UI changes, verify in a real browser.
- Single test: `bun test server.test.ts -t "<name substring>"`. The login-lockout test must stay last (it locks the global login). No client, `extension.ts`, or `shared.ts` tests; session listing is only tested with an empty list, and the delete test (WS `delete` of a `..` path errors and keeps the file; a real chat loses its `.jsonl` + artifacts dir) must run before the lockout test since it logs in.
